## Alternatives Considered

- **Own POSIX gate script (scripts/check-package.sh)**: checks name-versus-directory, description length and person, size and early iron law, which `claude plugin validate --strict` accepts silently (live probes recorded in `01-RESEARCH.md` Pitfall 4, 2026-10-17); validator scope per https://code.claude.com/docs/en/plugins-reference (read 2026-10-17). Needs only git, jq, tar and the claude CLI.
- **skills-ref validate (PyPI skills-ref 0.1.1)**: spec-conformance checker from https://agentskills.io/specification (read 2026-10-17); https://pypi.org/project/skills-ref/ published 2026-01-10; legitimacy audit verdict SUS (unknown downloads), and it adds a Python package install.
- **claude plugin eval cases**: behavioural regression suite per https://code.claude.com/docs/en/plugin-evals (read 2026-10-17); deferred in 01-CONTEXT.md and slower than static checks.

Decided by: simplicity (no new dependency, one POSIX file); performance ties for the static checks.

### Internal design alternatives

- **Export via git stash create plus git archive**: chosen; covers staged and committed tracked files, skips untracked root CLAUDE.md, works inside linked worktrees.
- **git clone of the repo root**: the research prototype; behaviour when cloning from a linked worktree path was not verified.
- **Validate the working tree in place**: fails strict because of the untracked root CLAUDE.md (Pitfall 1).
